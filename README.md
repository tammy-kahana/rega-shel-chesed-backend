# רגע של חסד - שרת (Backend)

שרת למערכת שמחברת בין משימות חסד בקהילה לבין מתנדבים מאושרים.
רכזי התנדבויות מפרסמים משימות, ומתנדבים מצטרפים אליהן.

> 🚀 **להעלאה לאינטרנט בפעם הראשונה:** פתחי את [START-HERE.md](START-HERE.md).
> 🧩 **לכתיבת צד ה-React:** פתחי את [FRONTEND-API-GUIDE.md](FRONTEND-API-GUIDE.md).

---

## טכנולוגיות

| מה | למה |
| --- | --- |
| Node.js 22 + Express | השרת עצמו |
| TypeScript (strict) | קוד עם בדיקת טיפוסים |
| PostgreSQL | מסד הנתונים |
| Prisma | גישה למסד הנתונים, סכמה ו-Migrations |
| Zod | בדיקת תקינות של מה שנשלח לשרת |
| JWT + bcryptjs | התחברות, וסיסמאות מוצפנות |
| Swagger (OpenAPI 3) | תיעוד ובדיקה של ה-API בדפדפן |
| Vitest + Supertest | בדיקות אוטומטיות |

## מבנה התיקיות

```
backend-project/
├── src/
│   ├── server.ts            נקודת הכניסה - מפעיל את השרת
│   ├── app.ts               הרכבת Express: CORS, JSON, Swagger, נתיבים, שגיאות
│   ├── config/env.ts        טעינה ובדיקה של משתני הסביבה
│   ├── db/prisma.ts         החיבור למסד הנתונים
│   ├── routes/              איזו כתובת מפעילה איזו פעולה (וההרשאות שלה)
│   ├── controllers/         מקבלים בקשה ומחזירים תשובה
│   ├── services/            הלוגיקה: הרשאות צפייה, הצטרפות, סטטוסים...
│   ├── schemas/             ולידציה עם Zod (הודעות שגיאה בעברית)
│   ├── middleware/          אימות Token, הרשאות, ולידציה, טיפול בשגיאות
│   ├── constants/labels.ts  השמות בעברית של כל ערכי הבחירה
│   ├── docs/openapi.ts      תיעוד Swagger
│   └── utils/               עזרים קטנים (תאריכים, שגיאות)
├── prisma/
│   ├── schema.prisma        מבנה מסד הנתונים
│   ├── migrations/          קובצי SQL שיוצרים את הטבלאות
│   └── seed.ts              נתוני הדגמה
├── tests/                   בדיקות אוטומטיות
├── docs/openapi.json        תיעוד ה-API כקובץ
├── render.yaml              הגדרות פריסה ל-Render
├── START-HERE.md            מדריך העלאה לאינטרנט
└── FRONTEND-API-GUIDE.md    מדריך לחיבור ה-React
```

**מסלול של בקשה:** `routes` (כתובת + בדיקת Token + הרשאה + ולידציה) ← `controllers` ← `services` (הלוגיקה + Prisma) ← מסד הנתונים. כל שגיאה בדרך מגיעה ל-`middleware/errorHandler.ts`, שמחזיר JSON אחיד בעברית.

## מסד הנתונים

שלוש טבלאות:

| טבלה | מה שומרת | קשרים |
| --- | --- | --- |
| `users` | משתמשים: שם, טלפון, סיסמה מוצפנת, תפקיד (רכז/ת או מתנדב), סטטוס אישור | יוצר/ת הרבה משימות, משתתף/ת בהרבה הצטרפויות |
| `tasks` | משימות: כותרת, תיאור, סוג, אזור, תאריך, שעה, כמות מתנדבים, פרטים למתנדבים, סטטוס | שייכת לרכז/ת שיצר/ה אותה (`createdById`) |
| `signups` | הצטרפויות: מי הצטרף לאיזו משימה, פעיל או בוטל, האם דיווח ביצוע | מחברת בין `users` ל-`tasks` (קשר רבים-לרבים) |

אילוצים: טלפון ייחודי, מתנדב מופיע פעם אחת לכל משימה, כמות מתנדבים 1 עד 20, שעה בפורמט HH:mm.

## הרצה במחשב (לא חובה - אפשר לעבוד ישר מול השרת בענן)

צריך: Node.js 22 ומעלה, ו-PostgreSQL מותקן (או מסד נתונים ב-Neon).

```bash
npm install
copy .env.example .env        # ב-Mac/Linux: cp .env.example .env
# עכשיו לפתוח את .env ולמלא DATABASE_URL ו-JWT_SECRET
npx prisma migrate deploy      # יוצר את הטבלאות
npm run db:seed                # ממלא נתוני הדגמה
npm run dev                    # מפעיל את השרת: http://localhost:3000/api-docs
```

> **אם יש סינון אינטרנט (נטפרי וכדומה)** ו-`npm install` או `prisma` נכשלים בשגיאת תעודה: צריך להגדיר את המשתנה `NODE_EXTRA_CA_CERTS` לקובץ התעודה של הסינון. פרטים בטבלת התקלות ב-START-HERE.md.

## איך להסביר את השרת בבדיקה

**לאיזה API ה-React פונה?** לכתובת השרת, ותמיד לנתיבים שמתחילים ב-`/api`. למשל רשימת המשימות: `GET /api/tasks`.

**מה נשלח לשרת?** JSON בגוף הבקשה (למשל טופס משימה), פרמטרים בכתובת (למשל `?area=ELAD` לסינון), ובכל בקשה מוגנת - כותרת `Authorization: Bearer <token>`.

**מה חוזר מהשרת?** JSON. בהצלחה - הנתונים (משימה, רשימה, משתמש). בשגיאה - קוד מתאים (400, 401, 403, 404, 409) והודעה בעברית בשדה `message`.

**איך נשמר המידע?** ב-PostgreSQL, בשלוש טבלאות. השרת ניגש אליהן דרך Prisma. הסטטוס של משימה (פתוחה/נתפסה) מחושב בשרת מחדש בכל הצטרפות או ביטול, בתוך טרנזקציה שנועלת את המשימה, כך ששני אנשים לא יתפסו את המקום האחרון.

**איך עובדת ההתחברות?**
1. המשתמש שולח טלפון וסיסמה ל-`POST /api/auth/login`.
2. השרת משווה את הסיסמה ל-Hash השמור (הסיסמה עצמה לא נשמרת אף פעם).
3. השרת מחזיר JWT - "כרטיס כניסה" חתום, שתקף 8 שעות.
4. ה-React שומר אותו ושולח אותו בכל בקשה.

**איך עובדות ההרשאות?** בכל בקשה השרת בודק את ה-Token, טוען את המשתמש ממסד הנתונים, ומחליט לפי התפקיד והסטטוס שלו. ההחלטה תמיד בשרת: גם אם מישהו "יעקוף" את ה-React, השרת יחזיר 403. המשתמש נקבע לפי ה-Token בלבד, ולא לפי מזהה שהלקוח שולח.
